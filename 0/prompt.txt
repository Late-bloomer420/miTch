**Root cause chain:**

1. `main.tsx:7` mounts `<App />` inside `<React.StrictMode>`. In development builds, StrictMode intentionally mounts components, runs effects, unmounts, and re-runs effects once to surface missing cleanup.
2. The bootstrap effect at `App.tsx:356–398` has an empty dependency array and **no cleanup function**: it calls `init()` unconditionally at the end (`App.tsx:397`). So in dev the whole sequence — `🔓 Initializing Wallet Service...` → `🔑 Wallet Decrypted & Ready` → passkey status line → credential load — runs twice, and each `addLog` call appends (`App.tsx:256`, `setLogs(prev => [...prev, ...])`). Hence every startup line appears twice.
3. In a **production build, StrictMode's double-invocation does not occur**, so users never see this. It's dev-only as a *visual* symptom.

**Why it's not entirely benign:**

The effect has real side effects beyond logging: `walletRef.current.initialize('123456')` and the WebAuthn availability/identity checks (`App.tsx:358–387`) run twice in dev. The log doubling is the *visible* evidence that the bootstrap isn't idempotent. On the first (discarded) StrictMode pass, `initialize()` decrypts the vault and the async passkey checks fire — the second pass then re-initializes an already-initialized wallet. If `WalletService.initialize()` isn't safe to call twice, the duplicate could mask or cause state races. That's worth checking in `WalletService.ts` even though the symptom is cosmetic.

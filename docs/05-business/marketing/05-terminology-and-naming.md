# miTch Terminology and Naming

Stand: 2026-05-21

This file is the canonical naming reference for product, marketing, and demo copy.

## Canonical terms

- `miTch` - product name.
- `The Forgetting Layer` - public brand line.
- `Identity Firewall` - technical capability name for tracker / identifier visibility.
- `DecisionCapsule` - policy decision artifact.
- `DataFlow` - internal transaction view for audit and proof activity.

## Preferred usage

- Use `miTch` when naming the product.
- Use `The Forgetting Layer` when describing the brand position.
- Use `Identity Firewall` when describing identifier / tracker visibility.
- Use `DataFlow` when describing the transaction trace in the wallet.
- Use `DecisionCapsule` when describing the signed policy result.

## Avoid or restrict

- Avoid calling the product only a `privacy app`. That is too broad.
- Avoid calling `DataFlow` the user-facing product. It is a view, not the brand.
- Avoid saying `blocking` unless the code actually blocks something.
- Avoid saying `full audit trail` if the supporting evidence is not linked.
- Avoid using `Privacy Audit` as the main product label in marketing copy. It sounds generic and under-describes the feature.

## Recommended external vocabulary

- `minimum proof`
- `selective disclosure`
- `fail-closed policy`
- `audit evidence`
- `identifier visibility`
- `decision-bound flow`

## Recommended internal vocabulary

- `identity-access event`
- `claim withholding`
- `proof mediation`
- `transaction grouping by decision_id`
- `PII-minimal metadata`

## Naming rule

If a term can be mistaken for a generic privacy feature, prefer the more specific term.
